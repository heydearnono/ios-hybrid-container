## 取值落地

一律取 `pro` 的取值表，本仓不自定。

| 取值 | 字符串 | 写在哪 | 校验 |
| --- | --- | --- | --- |
| 标识 | `net.xiaoluzhu.crab` | `PRODUCT_BUNDLE_IDENTIFIER` | `verify.sh` 读产物 `CFBundleIdentifier` |
| 应用名 | `Crab` | `PRODUCT_NAME` / `INFOPLIST_KEY_CFBundleDisplayName` | 屏上显示 |
| 中文显示名 | 螃蟹 | `App/Resources/zh-Hans.lproj/InfoPlist.strings` | `verify.sh` 读产物 `zh-Hans.lproj/InfoPlist.strings` |
| 最低系统版本 | iOS 26.0 | `options.deploymentTarget.iOS` | 低于它的模拟器会被 Xcode 全部过滤掉 |
| 应用版本 | `0.1.0` | `MARKETING_VERSION` | `verify.sh` 读产物 `CFBundleShortVersionString` |

**版本这一项现在只是落个地。** 它的用处在 M3：UA 要拼成 `Crab/0.1.0`，取值处就是
`CFBundleShortVersionString`，不取构建号、不取模块版本。

**中文名要一份 `.lproj` 资源。** 只在 Info.plist 里写 `CFBundleDisplayName` 落不到中文名 ——
`pro` 的 M1 说「三端各要一份中文本地化资源」，iOS 这边就是这份 `InfoPlist.strings`；
放哪属端侧工程事实，所以记在这里而不是回 `pro`。

## `scripts/probe.sh` 骨架

三仓同名，输出形状三端一字不差：一行一条 `<slug> PASS|FAIL|MANUAL`，slug 与顺序照 `pro` 的文档顺序
固定（M2 六条、M3 两条、M4 八条，合计十六条）。

M1 阶段十六条一条也没实现，所以它**只落 slug 清单与输出形状**，跑起来走 stderr 说清「还没接」，
退出码 2。刻意不打印任何 `PASS` / `FAIL`：假的 `PASS` 会污染对账记录，而 `FAIL` 的意思是「断言跑了
没过」，不是「还没写」。`./scripts/probe.sh slugs` 单独打那份清单与顺序。

## M1「要试出来的」：iOS 只认领一条

`pro` 那张表四条，其余三条是鸿蒙的。

| 要试什么 | 结果 |
| --- | --- |
| iOS 的 bundle id 收不收下划线 | **收，但报 warning。** 见下 |

把标识临时改成 `net.xiaoluzhu.crab_probe` 试了一次完整构建（Xcode 26.2）：

```
warning: invalid character in Bundle Identifier. This string must be a uniform type
identifier (UTI) that contains only alphanumeric (A-Z,a-z,0-9), hyphen (-), and period (.)
characters. (in target 'Crab' from project 'Crab')
** BUILD SUCCEEDED **
```

产物里的 `CFBundleIdentifier` 就是带下划线那一串，`simctl install` 与 `launch` 都成立。所以：

- **构建期不拦**，只是 warning；模拟器照装照起
- 但 Xcode 自己吐的规则原文明确把合法字符限定在 **字母数字、连字符、点**，下划线不在内
- ⚠️ 未验证：签名、真机与上架阶段会不会硬拦。本阶段签名全关，碰不到那一层

**这不改取值** —— 现取的形状（全小写、只用字母、点分三段）本来就避开了下划线与连字符。它补的是
`pro` M1 里「形状核过」那句依据：依据是 Xcode 的这条 warning 原文与 Apple 的 UTI 规则，
**不是「构建会失败」**。这条属平台事实，交回 `pro`，本仓不留第二处。

试完已还原：标识改回 `net.xiaoluzhu.crab`，probe 那个 app 从模拟器卸掉，中间产物删掉。
