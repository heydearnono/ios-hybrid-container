# 03 · 云端 LLM 与 iOS 客户端架构

**主线目标**：需要最强模型能力时，iOS 端怎么接、架构怎么摆、成本与风险怎么算。

## 范围

- 架构选择：设备直连大模型 API vs. 自建后端代理（这是安全问题，不是偏好问题）
- 密钥管理：为什么 API Key 绝不能打进 App 包体
- Swift 侧流式响应（SSE）处理、取消、重试、超时
- 端云协同：什么请求走端侧、什么走云端、怎么降级
- 成本与延迟测算方法

## 安全底线

🔴 **API Key 打进 App 二进制等于公开**。App 包可以被解包，字符串可以被 dump，
HTTPS 流量可以被抓包。任何「藏在代码里」「做了混淆」的方案都不成立。
默认架构是自建后端代理，设备只持有用户态凭证。这条不需要再调研，只需要在设计里落实。

## 与其他主线的区别

⚠️ **Apple 对第三方云端 LLM 的接入不提供任何官方指引**。本目录的结论没有官方文档可引，
因此这里的笔记性质与 01/02/04 不同：**是自己做的设计文档，不是文档摘录**。
写作时的证据标准相应调整为「给出方案 + 明确取舍与风险」，而不是「附官方链接」。
参见 [`../00-overview/ios-ai-landscape.md`](../00-overview/ios-ai-landscape.md) 路径 4。
