## 结论先行：代码已就位，模拟器那一遍**没能跑**

六条断言的实现、承载 handler、探针页、`probe.sh` 的 run 分支都写完了，但这台机器
**没同意 Xcode 许可协议**，`swift`、`xcodebuild`、`simctl` 全部被挡在同一句话上：

```
You have not agreed to the Xcode license agreements.
Please run 'sudo xcodebuild -license' ...
```

解除要 `sudo xcodebuild -license accept`，需要 root 口令——AI 这边拿不到，也不替用户同意一份
协议。所以 `verify.sh logic`（`swift test`）与 `probe.sh run`（`simctl` 挑设备那一步）都在许可这关
退出，**六条一条也没真跑过**。下面每条的状态因此都是「代码就位，未跑 `[待确认]`」，不是 PASS。

**绝对没有打印假的 PASS。** `probe.sh run` 现在跑的话会停在「挑一台模拟器」那步报许可错误、退出非零；
`probe.sh slugs` 不碰 Xcode，照常列出十六条 slug（已验证，退出码 0）。

## 解除许可后怎么补这一遍

```bash
sudo xcodebuild -license accept        # 需要口令，一次性
./scripts/verify.sh logic              # 包内四类单测：路径归一化 + 单点定义检查
./scripts/probe.sh run                 # 模拟器上跑 M2 六条，结果落 .probe/m2-probe.txt
```

## 承载实现要点（对着 pro 的 iOS 一节与「要做到什么」逐条）

- **自定义 scheme + `WKURLSchemeHandler`**：`App/CrabSchemeHandler.swift`。scheme 取
  `HostingOrigin.scheme`（从承载 origin 派生）。
- **先判 host**：非 `HostingOrigin.host` 的请求一律 404。`setURLSchemeHandler` 按 scheme 注册、
  不看 host（pro 平台事实），所以这道判定必须在 handler 里自己做。
- **承载 origin 端内只定义一处**：`Packages/CrabHosting/Sources/CrabHosting/HostingOrigin.swift`
  的 `origin` 那一行是唯一字面量，`scheme` / `host` 都从它解析。host 判定、注入范围判定（M3）、
  导航放行判定（M4）都从它派生。
- **那条「只出现一处」的可执行检查**：`SingleDefinitionTests` 扫 `App/` 与包的 `Sources/`，断言
  整串只出现一次（不扫 `Spikes/`——它是一次性 spike，不是实现）。走查不算，这是单测。
- **路径归一化**：`HostingPath.resolve`，纯函数、`HostingPathTests` 覆盖明文越界、编码越界、
  `.`/`..` 消解、刚好回到根不算越界。handler 另加一道「落点必须在承载目录内」兜底。
- **承载目录与越界目标的磁盘关系**：启动时把 `index.html` / `probe.js` / `probe.png` 落到
  `Documents/hosting/`，`out-of-bounds.txt`（内容 `OUT_OF_BOUNDS`）落到 `Documents/`（hosting 的父目录），
  这样编码 `..` 真有一个承载目录可爬——naive handler 会漏，正确的归一化拦住。

## origin 那条不是永久结论

pro 的平台事实写明：iOS 自定义 scheme 拿到 tuple origin 靠的是 WebKit 偏离 WHATWG 规范，
**iOS 每升一个大版本，`origin` 这条要当回归重跑**。所以这里不写「已永久成立」——这一遍（真跑之后）
只对当时那个 iOS 模拟器档位成立。
